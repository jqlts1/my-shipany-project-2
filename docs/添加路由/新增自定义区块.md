## 新增自定义区块

这一页专门讲“怎么加一个你自己的 landing 区块（block）”，给主题页面用。

## 注意
1. 所有的文本内容! 只能通过json传递! 不要写死!

### 三步快速上手

**Step 1：在主题下创建区块文件**

路径：

```
src/themes/<theme>/blocks/<block-name>.tsx
```

示例（文件名用 kebab-case，组件导出用 PascalCase）：

```tsx
// src/themes/<theme>/blocks/my-block.tsx
'use client';

import { Section } from '@/shared/types/blocks/landing';

export function MyBlock({ section }: { section: Section }) {
  return (
    <section id={section.id}>
      <h2>{section.title}</h2>
      <p>{section.description}</p>
    </section>
  );
}
```

**Step 2：在页面 JSON 中引用**

```json
{
  "page": {
    "sections": {
      "my_section": {
        "block": "my-block",
        "id": "my-section",
        "title": "My Block Title",
        "description": "anything you need"
      }
    }
  }
}
```

**Step 3：如果区块需要额外 props**

默认情况下 DynamicPage 只会传 `section` 给区块，所以：
- 组件签名是 `({ section })` → 不用改任何代码
- 组件需要别的 props → 必须在当前主题的 `DynamicPage` 加一个 `case` 做适配

```tsx
// src/themes/<theme>/pages/dynamic-page.tsx
case 'my-block':
  return <MyBlock section={section} extra={section.extra} />;
```

下面是细节规则（遇到问题时对照即可）。

### 1) 区块文件应该放哪里？

区块文件永远放在**主题的 blocks 目录**下：

```
src/themes/<theme>/blocks/<block-name>.tsx
```

不是只能放 `default` 主题。  
例如你当前主题是 `aiwallpaper`，则应放在：

```
src/themes/aiwallpaper/blocks/my-block.tsx
```

DynamicPage 在渲染时会按当前启用主题优先加载：

1. `src/themes/<activeTheme>/blocks/<block-name>.tsx`
2. 找不到再 fallback 到 `src/themes/default/blocks/<block-name>.tsx`

因此：
- 想让某主题专用区块生效，需要把 `NEXT_PUBLIC_THEME` 设为该主题并重启 dev。
- 主题未切换时，看起来像“只能用 default”是正常现象。

### 2) block-name 的命名规则（文件名）

文件名必须使用 **kebab-case**（短横线命名）：

```
my-block.tsx     ✅
myBlock.tsx      ❌
MyBlock.tsx      ❌
```

`block-name` 会来自你 JSON 的：

优先级：`section.block` > `section.id` > `sections` 的 key  
最终得到的字符串会直接用于动态 import：

```
import(`@/themes/${theme}/blocks/${blockName}`)
```

所以文件名要和 `blockName` 完全一致。

### 3) 导出名规则（组件名）

区块组件的**导出名必须是 PascalCase（大驼峰）**，并且和文件名对应。

例如 `my-block.tsx` 推荐导出：

```tsx
// src/themes/<theme>/blocks/my-block.tsx
'use client';

import { Section } from '@/shared/types/blocks/landing';

export function MyBlock({ section }: { section: Section }) {
  return (
    <section id={section.id}>
      <h2>{section.title}</h2>
      <p>{section.description}</p>
    </section>
  );
}
```

加载规则是：
- 先尝试取 `PascalCase(blockName)` 的命名导出（推荐）
- 再尝试取同名导出（不推荐）

所以：
- `my-block` → `MyBlock` ✅
- `hero-tech` → `HeroTech` ✅
- 如果你导出成 `myBlock` / `my_block` 会找不到。

### 4) JSON 里如何引用？

在页面 JSON 的 `page.sections` 里通过 `block` 指定文件名（kebab-case）即可（见“三步快速上手”）。

### 5) 默认区块 vs 特殊区块（是否需要加 case）

**默认区块（SectionBlock）**  
组件只依赖 `section`：

```tsx
export function MyBlock({ section }: { section: Section }) { ... }
```

这种区块放进 `page.sections` 后会自动渲染。

**特殊区块（DataBlock）**  
组件除了 `section` 还需要额外 props：

```tsx
export function Pricing({ pricing }: { pricing: PricingType }) { ... }
```

这种必须在**当前主题**的 `DynamicPage` 里加一个 `case` 做 props 适配：

```tsx
// src/themes/<theme>/pages/dynamic-page.tsx
case 'pricing':
  return <Pricing pricing={section as any} />;
```

判断方法：看到区块组件的 props 不是 `({ section })` 时，就要加 case。

### 6) 你可以从 JSON 透传哪些字段？

DynamicPage 默认会把：
- `section`（包含 title/description/items/...）
- `page.data` 或 `section.data` 的自定义字段

直接传给区块组件。

因此你可以在 JSON 里任意加字段（例如 `label`、`buttons`、`highlight_text` 等），在区块里从 `section.xxx` 读取即可。

### 7) 常见错误（FAQ）

1. **Module not found: Can't resolve '@/themes/<theme>/blocks/<name>'**  
   - 当前主题下没有对应文件，或者文件名不是 kebab-case。  
   - 新增文件后记得重启 dev（尤其是 turbopack）。

2. **导出名不匹配**  
   - 文件名 `my-block.tsx` 但导出 `myBlock` / 默认导出，会导致找不到组件。

3. **主题没切换**  
   - 还在 `default` 主题时，系统不会加载 `aiwallpaper/blocks`。

如果你不确定 blockName 最终是什么，可以在 JSON 里显式写 `block` 字段，避免和 key/id 混淆。
